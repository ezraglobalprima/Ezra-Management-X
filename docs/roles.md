# Roles & Permissions

Ezra Management X can use a role-based access model.

A recommended hierarchy for the project is:

1. Developer
2. Owner Utama
3. Owner
4. Admin
5. Reseller
6. Moderator
7. VIP
8. Member

## Developer

The highest project-level role. Developer access should be controlled through a trusted configuration such as developer IDs.

## Owner Utama

Primary owner-level administration.

## Owner

Owner-level management permissions.

## Admin

Administrative group/bot management.

## Reseller

Business/reseller-related capabilities where enabled.

## Moderator

Moderation capabilities.

## VIP

Additional privileges above regular members.

## Member

Basic user access.

> The actual permissions of each role depend on the current implementation. Do not assume a role grants a capability unless it is implemented and documented.
